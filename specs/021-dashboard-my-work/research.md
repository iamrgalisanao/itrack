# Research — 021 Dashboard Restructure with My Work List

**Date**: 2026-08-26. Produced by a four-perspective Software Architect orchestration
(backend, frontend, design governance, security/testing) with an adversarial cross-check.
Where perspectives conflicted, the cross-check's resolution is recorded here and is
binding. All file/line references verified against the working tree on this date.

## Verified ground truths

- `GET /api/dashboard` → `ProjectController::dashboard()` (`backend/app/Http/Controllers/ProjectController.php:254-345`), consumed by **two** callers: `Dashboard.jsx:366` and `App.jsx:154` (sidebar reads `stats`). Two `ProjectScopingTest` assertions pin `stats.projects`. ⇒ payload changes must be additive.
- `DetailedActivity` has **no `due_date` column** — the due date is `plan_end_date` (cast `date`). Assignee is `assignee_user_id` (FK, indexed). Status is a NOT NULL string over `backlog, not_started, in_progress, for_review, completed, blocked, delayed`; **"open" = `status != 'completed'`**. Today's dashboard counts recognize only 4 of the 7 statuses — `backlog`/`for_review`/`blocked` tasks vanish from the current stat cards (defect the new metric row must not reproduce).
- Team Members cannot set assignees (`assignee_user_id` deliberately outside `$allowedForTeamMember`, `DetailedActivityController.php:199-205`, an 018 policy) and **Clients can never be assignees** (`internalUserExistsRule()` excludes `ROLE_CLIENT`) ⇒ a Client's My Work list is structurally empty; render read-only anyway (spec scenario 6).
- Middleware chain (`routes/api.php:50`): `auth:sanctum → EnsureUserIsActive → ResolvePreviewSession → BlockWritesDuringPreview`. Routes registered inside it get preview-aware reads (via `AccessContext::user()`) and preview write-blocking for free.
- Denial convention: TM/Client get **403 with byte-identical bodies** for inaccessible AND nonexistent resources (no existence oracle); Admin/PM/DH get 404 for nonexistent.
- Frontend: preview token auto-attached by the `api.js` request interceptor — no frontend preview code needed. `index.css:104-106` unlayered border reset makes `border-l-*` accents inert app-wide — accents must be absolute `bg-*` spans (note: `StatCard`'s existing `border-l-4 ${accent}` prop is already inert for the same reason — fix or drop while touching the summary row). `GroupSummaryBar.jsx` documents the `table-fixed` + percentage-widths-summing-to-100 contract. `TodayDashboard.jsx` has **no** My-Work-like list (Support-Ops SLA buckets only) — no overlap.
- **Team Members cannot edit `plan_end_date`/`plan_start_date`** — both are outside `$allowedForTeamMember` (`DetailedActivityController.php:199-208`, existing 002/018 policy): a TM's modal date edit is silently stripped (200, field unchanged). **Accepted as intended policy for 021** — TM re-bucketing via due date is out of scope; FR-005 date-driven re-bucketing applies to PM/Admin. Recorded in quickstart step 3's role annotation; a modal UI affordance fix (disable/annotate date fields for TM) is a deferred follow-up.
- **Concurrent status edits are last-write-wins** — `DetailedActivityController::update()` has no optimistic-concurrency precondition; two sessions editing the same task's status resolve to the latest write (each change audited via `task.status_changed`). **Accepted for 021** (spec edge case amended to match): stale-row *errors* arise only from deletion/revocation (403/404), which the panel surfaces and refetches on. A lightweight `updated_at` precondition (409 on mismatch) was considered and rejected as new endpoint surface out of proportion to the risk.

### Pre-existing defects found during the audit (in-scope fixes)

1. **`recent_activities` leaks internal tasks to Clients** — `dashboard()` does not filter `client_visible` for the Client role, unlike `DetailedActivityController::index()`. Fixed in this feature while touching the method; test required (see Test-requirements).
2. `team_members` / `glossary_terms` counts are **global**, not scoped. Cards are removed by FR-010; key cleanup deferred until the structure strip's content is confirmed (removal is a follow-up, not 021).

## Decisions

### R1 — My Work read: new `GET /api/my-work` (`MyWorkController::index`)
- **Decision**: New single-purpose controller inside the existing middleware group. Not part of `/api/dashboard`.
- **Rationale**: independent refresh cycle (status changes must not re-run the heatmap aggregation); `dashboard()` is already ~90 lines (SRP); house precedent for purpose controllers (`SupportOpsController`, `TaskboardController`).
- **Alternatives**: embed in dashboard payload (couples lifecycles; sidebar pays for it) — rejected; `apiResource` (not a CRUD resource) — rejected.

### R2 — Server-side bucketing; client-supplied local-date anchors *(cross-check resolution of a 3-way conflict)*
- **Decision**: Server groups into `overdue / this_week / later / no_due_date` from validated query params `today` (Y-m-d) and `week_end` (Y-m-d, `after_or_equal:today`), accepted **only as an all-or-nothing pair** — a lone anchor is 422 (`required_with` both directions); when absent the server computes **both** defaults (server-tz today / end-of-week), never a mixed client/server state, because mixed anchors make the predicates overlap and break count integrity. Post-validation the controller asserts `today <= week_end`; invariant: the four counts always partition (sum to) the open total. Predicates: `overdue < today`; `today ≤ this_week ≤ week_end`; `later > week_end`; `no_due_date IS NULL`. Per-bucket cap `per_bucket` (default 10, `max:100`) with **true totals**; `?bucket=X&all=1` expands one bucket uncapped (`bucket` and `all` must appear together, else 422).
- **Rationale**: FR-013 (capped rows + true counts) is only enforceable server-side with a bounded payload; spec pins boundaries to the user's local timezone and the browser is the only tz authority (no user-tz column exists; adding one violates "no new settings"); date anchors avoid IANA-tz validation/DST surface — the client computes end-of-week anyway for the quick-add prefill; boundaries become PHPUnit-testable with literal dates.
- **Alternatives**: client-side bucketing over a flat list (cap becomes cosmetic; unbounded payload for many-project PMs; counts untestable server-side) — rejected; `?tz=` IANA param (validation + DST surface for no gain) — rejected; stored user timezone (new settings surface) — rejected.
- **Consequences (binding)**: status changes never re-bucket (buckets key on due date) so optimistic inline status handling is safe; any **due-date** change (modal save) triggers a panel refetch of `GET /api/my-work` — no client-side re-merge (owns FR-005's "reflected when it closes").

### R3 — Query shape: 6 queries, no migration
- **Decision**: (1) accessible-project pluck via `Project::accessibleTo($user)` — `$user = AccessContext::user($request)`; (2) one aggregate `SUM(CASE WHEN …)` count query over the anchors (SQLite+MySQL portable, parameter-bound); (3) four capped row queries cloned from a base builder: `assignee_user_id = $user->id` ∧ `scopeOpen()` ∧ `whereHas('subActivity.activity.module', whereIn project_id)` ∧ `client_visible = true` when `$user->isClient()` (defense-in-depth; normally moot). Rows ordered `plan_end_date, id` (`no_due_date`: `created_at` desc), `->with(['subActivity.activity.module.project'])`.
- **Rationale**: the `whereHas`+`whereIn` shape is exactly `TaskboardController::index()`'s — tenant isolation reviewed once, reused. `assignee_user_id` FK index makes the selective predicate cheap. New `scopeOpen()` prevents re-typing the open definition in the metrics.
- **Alternatives**: single query + PHP partition (defeats capping) — rejected; window functions (raw-SQL portability risk, unjustified at 4×10 rows) — rejected; denormalized `project_id` + composite index `(assignee_user_id, status, plan_end_date)` — **deferred follow-up**, recorded as the scaling lever; not part of 021 (Constitution V).

### R4 — Response contract: lean `MyWorkTaskResource`, fixed-shape envelope *(cross-check resolution)*
- **Decision**: Row fields exactly: `id, name, code, status, progress, plan_end_date, priority, sub_activity_id, project{id,name}, module{id,name}`. Envelope always contains **all four buckets** (`{count, tasks[]}` — empty ⇒ `count: 0, tasks: []`) plus `meta{today, week_end, per_bucket, can_write}`. `can_write = AccessContext::user($request)->canWrite()` (effective role ⇒ preview-correct).
- **Rationale**: reusing the ~30-field `DetailedActivityResource` ships Support-Ops internals (`root_cause`, `resolution`, `evidence`, `notes`, …) to a list that never renders them (Principle II / excessive-exposure). Fixed shape is the stabler contract; FR-011's empty-bucket omission is a **rendering** rule, not a payload rule.
- **Consequence (binding)**: row click fetches the full task via existing `GET /api/detailed-activities/{id}` before/while opening `TaskDetailModal` (the one new loading treatment: disable the row or open the modal shell with a spinner — implementer's choice, but it must be visible). The frontend demand for a full-task-shaped list resource is **rejected** (conflicted with the payload-discipline test that bans `notes`).

### R5 — Inline status change reuses `PUT /api/detailed-activities/{id}` unchanged
- **Decision**: The row `<select>` calls the existing update endpoint with `{status, progress}` (Kanban's auto-progress coupling: `completed→100`, `not_started|backlog→0`). Optimistic with rollback (Kanban precedent, `Kanban.jsx:216-240`); on 403/404/409 additionally hard-refetch the panel (stale-row edge case). Completing removes the row optimistically.
- **Rationale**: the endpoint already carries tenant check, `canWrite()`, TM field-stripping, `task.status_changed` audit, blocked-task notifications, preview blocking — zero new authorization surface. Buckets key on due date, so the classic optimistic hazard (mis-bucketing) is absent.
- **Alternatives**: dedicated `PATCH /my-work/tasks/{id}/status` (duplicate authz stack) — rejected; refetch-per-change (visible 4-bucket flicker, unnecessary) — rejected.

### R6 — Quick-add: new `POST /api/my-work/tasks` with forced self-assignment *(cross-check resolution)*
- **Decision**: `{name: required|string|max:255, module_id: required|exists + accessible-project check, plan_end_date: nullable|date}`. Gates in order: `canWrite()` on the **effective** user (denial → `AuditLogger::denied`), then module's project ∈ `accessibleTo`. Creates inside a `DB::transaction` with `assignee_user_id = $request->user()->id` **hard-coded server-side** (client-supplied value ignored, not 422), `status = 'not_started'`, placed via the reserved `Taskboard`/`Unclassified Tasks` chain. Audits `task.created` (real user). Returns 201 + `MyWorkTaskResource`. Due-date prefill (This Week → local end of week) is computed client-side and sent as an ordinary date.
- **Rationale**: extending the shared `DetailedActivityController::store()` with `assignee_user_id` would re-open the assign-anyone loophole 018 deliberately closed for Team Members (`DetailedActivityController.php:240` comment); `TaskboardController::store()` is PM/Admin-only by 018 policy. FR-006's "assigned to the acting user" is a fail-closed **server invariant**, not a frontend promise. `module_id` placement keeps quick-add at title + placement (FR-007/SC-004); server-side chain resolution is the established 018 convention.
- **Alternatives**: extend shared `store()` (018 regression risk) — rejected; `sub_activity_id` placement (forces 4-level picker, breaks the 2-input budget) — rejected, noted as a future `?placement=deep` extension; PM/Admin-only (contradicts US3) — rejected.
- **Extraction (binding)**: `resolveDefaultSubActivity()` + the two reserved-name constants move from `TaskboardController` to `App\Support\TaskboardPlacement` (static, caller-owns-transaction documented). Unlike the accepted `internalUserExistsRule()` duplication, the reserved *names* are correctness-coupled — drift would create a second parallel "Unclassified" bucket per module. This is the documented exception to the house small-duplication preference.
- **No assignment notification on quick-add**: `TaskboardController::store` notifies the assignee when one is set; `MyWorkController::store` always self-assigns, and notifying users about their own quick-adds is noise — the store action deliberately skips the assignment notification (test-asserted). Do not pattern-match Taskboard's notification call.

### R7 — Dashboard summary: additive payload; metric set *(cross-check resolution)*
- **Decision**: Keep `GET /api/dashboard` and every existing key. Add `completed_recent` = accessible tasks with `status='completed'` and `updated_at >= now()->subDays(7)` (documented proxy — `actual_end_date` too sparsely populated), **filtered by `client_visible` when the effective user `isClient()`** (new prominently-rendered key ⇒ Client exposure reasoned explicitly per Delivery Constraints). Fix the `recent_activities` Client `client_visible` leak in the same touch. Metric row renders: **Completed (7d) → Overall Progress % → In Progress → Delayed**; the progress card's description must not repeat the completed count (SC-002). `not_started` leaves the page-level metrics (visible per-module in the heatmap). Heatmap `<tfoot>` totals row (Dashboard.jsx:328-347) is **removed** — it would re-duplicate In Progress/Delayed.
- **Alternatives**: `/api/dashboard/v2` (versioning ceremony for a 2-consumer internal API) — rejected; removing dead keys now (breaks sidebar; removal is a later cleanup) — rejected; all-time Completed or "Remaining (open)" metric variants — rejected by cross-check (spec's Key Entities names "completed recently"; accomplishment-first reads as recency).

### R8 — Frontend architecture *(cross-check-reconciled)*
- `MyWorkPanel.jsx` is **self-contained**: own `fetchMyWork()` (new `api.js` helper passing `today`/`week_end` computed from the browser locale, week ending Sunday per spec), own loading/error/collapse/reveal/quick-add/modal state; single `onTaskMutated()` callback prop → a **non-blanking `refresh()`** on the Dashboard. Rationale: independent failure domains (TodayDashboard's "one panel error never blanks the page" rule); `TaskboardView` precedent.
- **Dashboard `load()` split (architect-review condition)**: today's `load()` sets `loading=true` which renders the full-page spinner and unmounts everything — passing it as `onTaskMutated` would flash the whole page on every inline status change, defeating SC-001. Split into `load()` (initial mount, spinner) and `refresh()` (silent refetch, keeps stale data until the response lands); `onTaskMutated={refresh}`. This deliberately re-runs the dashboard aggregate (incl. heatmap) after each confirmed mutation — a freshness trade-off accepted over stale metrics, softened by coalescing rapid successive mutations if needed.
- **Refetch semantics**: a panel refetch (modal save, stale-row recovery) uses default params and **resets "Show all" expansions** to capped views — accepted; expansions are transient reveal state, not a filter. After an optimistic completion in a capped bucket the visible list may briefly under-fill (9 of 10) until the next refetch — accepted.
- **`StatCard` is kept** and reused for the four metrics (page-local `SummaryMetricsRow` is a thin wrapper); the hero, ring, chips, three grids, Needs Attention banner, and blur ornaments are deleted (lines in plan.md). Rationale: Existing-Design-System-First — `StatCard` already has the calm anatomy incl. conditional Delayed styling.
- **Status constants** (`STATUS_ORDER`, `STATUS_SEGMENT_LABELS`, `STATUS_SEGMENT_CLASSES`, `STATUS_BADGE_CLASSES` — the 7-status set) move from `TaskboardView.jsx` into a new **`frontend/src/lib/taskStatus.js`**; `TaskboardView` imports them (mechanical). A third copy, or the 4-status `LIST_STATUS_*` set (hides `backlog`/`for_review`/`blocked`), is prohibited. **Revised during pre-flight** (architect finding m1, adopted): the original plan put them in `GroupSummaryBar.jsx` citing a "mixed-export precedent" — but that precedent was itself producing two `react-refresh/only-export-components` **errors** that had been failing CI on `main`. Pre-flight commit `91779de` repaired the gate by extracting those value exports to `src/lib/groupSummary.js`; putting task-status constants back into the component file would reintroduce the same failure. `src/lib/` is now the established home for shared non-component values.
- **Fixed semantic accents via a panel-local map (architect-review condition)**: `MY_WORK_BUCKET_ACCENTS = { overdue: rose, this_week: amber, later: primary, no_due_date: slate }` defined **inside `MyWorkPanel.jsx`** (single consumer). **`GROUP_ACCENT_CLASSES` is not modified**: Taskboard, BugTracker, and Retrospectives all index it as `[index % length]`, so appending an entry changes the modulo cycle and recolors any of those views with 6+ groups — exactly the unrelated-page behavior change the completion gate prohibits. Index-rotation for My Work was already rejected (would randomly color Overdue emerald). Accents as absolute `bg-*` spans; `MY_WORK_COLUMN_WIDTHS` percentage strings summing to 100 shared by header row and `<colgroup>`.
- **Write affordances** gate on response `meta.can_write` (not a hardcoded role array — keeps the role→write mapping in `HasRole`, preview-correct); pre-data default renders nothing mutable. Quick-add additionally requires a non-empty accessible project/module list (a writable-role user with zero assignments must not see an empty picker). Panel-header **"+ Add task"** (visible when `can_write`) is the quick-add entry point for empty/omitted buckets — resolves FR-011's "except immediately after a quick-add interaction begins"; non-empty writable buckets also keep inline `QuickAddRow`; Overdue never offers quick-add.
- **Quick-add placement**: two dependent selects (Project via `fetchProjects()` → Module via `fetchModules(projectId)`), lazily loaded, MRU persisted in `localStorage` key `itrack.myWork.lastPlacement` (try/catch-guarded, validated against fresh lists — WorkProgram precedent). Flattened one-select hierarchy rejected (requires N `fetchModules` calls; no flat endpoint exists). `api.js` signature: `createMyWorkTask({module_id, name, plan_end_date})` — the project select is UI-only filter state.
- **Bucket-local UI state** (`closedBuckets`, `revealedBuckets`, `quickAdd`) is transient `useState` — not URL, not context, not storage. "Show all N" uses the fetch-backed `?bucket=X&all=1` expansion.
- **No route-level code splitting** introduced (above-the-fold content; first lazy boundary is out of scope).

### R9 — SC-002 audit rule *(cross-check Gap 7)*
The "no duplicated counts" audit applies to **component-level page totals only**: My Work's per-bucket `GroupSegmentBar` status *distributions* are not page-level status counts and do not violate SC-002. Surfaces enumerated for the audit: summary row, heatmap body/legend (tfoot removed), Recent Activities tabs (verified label-only), My Work headers.

### R10 — Explicitly rejected report positions (do not resurrect)
Client-side bucketing over a flat list; full-task-shaped list resource; "assigned-to-acting-user as a frontend contract"; extending shared `store()` with `assignee_user_id`; 4-status segment maps; flattened placement select; `StatCard` deletion; keeping the radial ring; hardcoded frontend role allowlist as the gating source; empty buckets omitted from the payload.

## Test-requirements (feeds /speckit-tasks — Constitution III & VIII)

New `backend/tests/Feature/MyWorkTest.php` (PHPUnit, `RefreshDatabase`, helper vocabulary from `ProjectScopingTest`/`TaskboardTest`: `startPreview()`, `callJsonPreviewing()` — headers via `json()`'s arg, never `withHeaders()`):

**`GET /api/my-work`** — all five roles reach it (200); 401 unauthenticated; 403 disabled user; TM sees only own open assigned tasks (completed/others'/unassigned excluded); all six open statuses included; Admin/PM still assignee-scoped ("My Work ≠ all work I can see"); DH scope; Client → 200 with valid empty shape; **user B's tasks never in user A's list**; **assigned task in inaccessible project excluded** (the assignee-alone-is-not-authorization test — most important in the feature); revoked assignment excluded on the very next request; bucket boundary matrix under `Carbon::setTestNow` (yesterday→overdue, +3d→this_week, +3w→later, null→no_due_date; due **today**→this_week; Sunday-morning boundary: due-that-Sunday→this_week, Monday→later); **anchor-param validation**: absent anchors → server defaults, 200; malformed `today` → 422; `week_end < today` → 422; `bucket=bogus` → 422; shifted anchors shift buckets; **caps**: 15 tasks in one bucket → rows ≤ `per_bucket` AND `count` = 15; `?bucket=this_week&all=1` uncaps that bucket only; **fixed shape**: empty buckets present as `count: 0, tasks: []`; **payload discipline**: `assertArrayNotHasKey` for `root_cause`, `resolution`, `evidence`, `client_name`, `tenant_name`, `notes`; parent-context names only from accessible chain; **`meta.can_write`**: false for Client and Department Head, true for TM/PM/Admin, and **false during Admin-preview-of-Client** (effective role); **preview**: previewed user's list returned, not Admin's; expired preview token → 409 + `X-Preview-Ended`, no domain data.

**Status change (deltas only** — role-gate basics live in `RoleAccessTest`, don't duplicate): completing removes from next read; **IDOR**: TM status-PUT on task in inaccessible project → 403 byte-identical to the nonexistent-id body; preview write → 403 + `preview.write_blocked` audit + DB unchanged; deleted task → 403 (TM) / 404 (Admin).

**`POST /api/my-work/tasks`**: role matrix (Admin/PM/TM → 201 + `task.created` audit; DH → 403 + `permission.denied` audit; Client → 403); **forced self-assignment**: payload-supplied `assignee_user_id` ignored, persisted row = acting user; bucket due-date prefill persists; inaccessible `module_id` → 403/422 (repo denial parity); **mass-assignment smuggling**: `client_visible`, `priority`, `sprint_label`, `id`, foreign `sub_activity_id` in payload → created row unaffected; validation errors (missing name; bad date) → 422 with `errors.name` shape (frontend inline-error contract); reserved-chain reuse (second quick-add in same module creates no duplicate Activity/SubActivity); quick-add during preview → blocked + `assertDatabaseMissing`.

**Dashboard additions**: `completed_recent` present with 7-day window boundary under `Carbon::setTestNow`; **Client sees no `client_visible=false` rows in `recent_activities`** (the defect fix's paired test); `stats.projects` preserved (reconcile with the two `ProjectScopingTest` assertions in the same change); counts remain `accessibleTo`-scoped.

**Anti-slop test rules**: assert observable behavior (status + JSON path + DB assertions); no mocking own collaborators; expected bucket dates as literals under frozen time — never re-implemented bucket math; no status-only tests. No `Tests\Unit` bucket class unless bucketing actually lands in a support class (don't create one to make it unit-testable).

## OWASP summary (scoped — full checklist run at sign-off)

- **A01**: double-filter (assignee ∩ accessibleTo) is the feature's core defense; route inside the 4-middleware group (outside silently drops `EnsureUserIsActive` + preview); `AccessContext::user()` for reads / real user for writes+audit; `HasRole` predicates only; denial parity preserved; frontend affordance-hiding is UI-only — server gates enforce.
- **A03**: explicit validated create-array; anchors validated and parameter-bound; no `$request->all()`.
- **Exposure**: lean resource (test-enforced ban list); assignee context never needed (always self); the `DetailedActivityResource` real-user Client-branch nuance during preview is **pre-existing intended behavior** — do not "fix" silently in 021.
- **A09**: no new audit categories; `MyWorkController::store` must call `AuditLogger` identically to house patterns.
- **N/A**: uploads, payments, SSRF, raw HTML (grep `dangerouslySetInnerHTML` in the diff), migrations.
